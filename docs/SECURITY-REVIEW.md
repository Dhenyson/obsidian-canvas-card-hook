# Security and automated review

Version 0.2.0 received 601 code/CSS warnings and four other findings. Of the code warnings, 596 concerned values the analyzer could not type-check. Reproducing the scanner rules locally confirmed the exact JavaScript counts. The previous local configuration omitted these type-aware rules; versions 0.2.1 and 0.2.2 correct that validation gap and complete the stylesheet cleanup.

## Changes completed in 0.2.2

The official community scan completed on October 16, 2026 for version 0.2.2 (commit `f18868c`). The public scorecard reports **Review: Passed**, seven passed checks, no code/CSS warnings, and two informational capability findings instead of the previous 605 findings. Both release-asset attestation checks and the byte-for-byte reproducible build check passed. The remaining findings are vault enumeration and clipboard access, explained below. The separate disclosure that a malware scan is unavailable still applies.

- Strict TypeScript source, typed public API imports, and explicit interfaces for the undocumented Canvas boundary.
- Runtime validation of parsed JSON before accessing hook, copied-card, or Canvas node fields.
- The complete recommended Obsidian lint configuration, with no warning suppression and zero warnings allowed.
- Native method wrappers that preserve receivers and arguments without `this` aliases.
- Specific CSS selectors instead of important overrides, checked at multiple zoom levels.
- GitHub build-provenance attestations for `main.js`, `manifest.json`, and `styles.css`, generated by the release workflow before release creation.

The runtime still has no network requests, telemetry, external accounts, or bundled runtime dependencies. Build tools run during development and CI, not in the installed plugin. Existing hook metadata and card links remain compatible. The interface is unchanged from 0.2.0, so the screenshots and animation remain representative.

## Intentional capabilities

**Clipboard:** explicit copy actions write a card reference. Paste processing reads the data supplied by the user's paste event. The plugin does not poll the clipboard or send its contents anywhere.

**Vault enumeration and reads:** rename handling obtains the vault file list, filters it to `.canvas` files, and updates matching hook destinations. Only Canvas content in the current vault is processed. This supports Canvas and folder renames; the file-list API also exposes vault file paths. It is an intentional capability rather than an access the plugin tries to conceal.

These capabilities may remain visible on the community scorecard. Their presence is distinct from source-code warnings. A clean lint result does not replace the community's independent review, and no particular scorecard badge is guaranteed.

Canvas integrations use internal methods because the public API does not cover native card rendering, creation, and viewport control. Types and guards improve maintainability but cannot guarantee compatibility with every future Obsidian version.

## Validation

Run `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `pnpm build`. The isolated desktop tests cover 76 behaviors, including navigation, native clipboard duplication, compact editing, rename updates, colors, creation menus, pointer dragging, read-only behavior, and unload/reload cleanup. Seven unit tests cover references, metadata escaping, malformed inputs, and preservation of unrelated Canvas fields.
